
# 25COB155 Mobile Application Development: Coursework Specification

**Loughborough University** **Assessment:** 100% of the total module mark  
**Task:** Native Android Application Development

---

## 1. Project Overview
Develop a native Android Application from scratch using **Android Studio** and **Kotlin**. This is an individual project where you must propose, design, develop, and reflect on a mobile application.

### Propose and Specify
* Propose an app of suitable complexity and specify the problem it solves.
* Define functionalities and technical requirement alignment.
* Design digital mock screens (sketches are acceptable if digitized).
* **Feedback:** One formative feedback session is available during labs/office hours before final submission.

---

## 2. Development Requirements (70%)

### Best Practices & Security (15%)
Apply module-taught best practices and security knowledge, supplemented by independent research.

### Mandatory Technical Requirements (25%)
* Minimum of **two distinct screens**.
* Use the **Navigation Component** for in-app movement.
* Use **Intent** for external app navigation.
* Handle **App Lifecycle** correctly (e.g., screen rotation).
* Create a custom **ContentProvider** with instrumented tests.
* Use local storage and manage permissions responsibly.
* *Note:* 3rd party libraries must be clearly referenced; automated logic/UI generators are prohibited.

### Optional Features - Select 3 (15%)
Choose exactly three from this list (no extra marks for more):
* Firebase for data storage/retrieval.
* Broadcast event handling.
* Android ShareSheet implementation.
* AI feature integration.
* Notifications.
* Adaptive layouts for different screen sizes.
* Touch gesture capturing.

### Quality & Usability (15%)
Marks awarded for code style, readability, complexity, and usability.

---

## 3. Video Demo (30%)
Submit a maximum **15-minute video** via Panopto including:
* Introduction to proposal and design.
* Functional demonstration.
* Implementation overview.
* Reflective comments on security and best practices.

---
