# SPECIFICATION & MARK MAXIMIZATION

## Core Objective
Strictly adhere to the [25COB155_CW_Specification.md](../../resources/25COB155_CW_Specification.md) to maximize marks for the coursework. All development decisions must be filtered through the marking criteria.

## 🎯 Mark Optimization Strategy

1. **Mandatory Technical Requirements (25%)**
   - Ensure a minimum of **two distinct screens**.
   - Use the **Navigation Component** for all internal transitions.
   - Implement **Intents** for external navigation.
   - Robustly handle the **App Lifecycle** (specifically configuration changes like rotation).
   - Implement a custom **ContentProvider** including comprehensive instrumented tests.
   - Manage local storage and permissions following Android best practices.

2. **Selected Optional Features (15%)**
   - Focus *only* on the selected 3 features. Do not waste effort on extra features as they yield no additional marks.
   - Ensure the selected 3 are implemented to a high standard.

3. **Best Practices & Security (15%)**
   - Apply module-taught patterns (MVVM, Repository pattern).
   - Document security considerations in code comments for easy reference during the reflective video demo.

4. **Quality & Usability (15%)**
   - Prioritize code readability, consistent naming, and logical structure.
   - Ensure a smooth, intuitive user experience.

5. **Demo Readiness (30%)**
   - Develop with the final 15-minute video demo in mind.
   - Maintain a log of key implementation challenges and security decisions to simplify the "Reflective comments" section of the video.

## 🚫 Critical Constraints
- **Originality**: Ensure all logic and UI structures are original and student-attainable.
- **Library Reference**: Clearly reference any 3rd party libraries used.
- **No Over-Engineering**: Avoid complex abstractions that aren't necessary for the coursework requirements.
